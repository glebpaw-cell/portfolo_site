# Портфолио Глеба

Статический сайт-портфолио на HTML, CSS и JavaScript. Он не требует установки пакетов, сборки, сервера или платного хостинга. Все пути относительные, поэтому сайт работает и как отдельный GitHub Pages сайт, и как проект по адресу вида username.github.io/repository-name/.

## Открыть локально

Самый простой способ — открыть index.html в браузере. Для локального сервера:

1. Открой папку portfolio-site в Терминале.
2. Запусти команду:

    python3 -m http.server 8000

3. Открой в браузере http://localhost:8000.

Интерактивный школьный макет открывается из кейса «Школьный сайт» внутри CSS-макета iPhone 15 Pro Max. Он загружается только после нажатия на кнопку, потому что автономный файл прототипа весит около 22 МБ.

## Что внутри

- index.html — текст, разделы, меню, аватар и контакт.
- styles.css — типографика, композиция, адаптивность и анимации.
- projects.js — данные кейсов и изображений; здесь удобнее всего добавлять работы.
- app.js — фильтры, карточки, просмотр изображений, мобильное меню и запуск школьного макета.
- assets/work/ — оптимизированные копии работ.
- assets/presentation/ — 17 изображений слайдов школьной презентации.
- assets/about/avatar.jpg — оптимизированная копия личного аватара.
- demos/school-prototype.html — самостоятельная копия интерактивного макета школы.

Папка исходных работ не нужна сайту после копирования. Все ресурсы, на которые ссылается портфолио, находятся внутри этой папки.

Архив содержит 38 материалов: 35 отдельных работ и три карточки проектов — школьный интерфейс, презентацию и серию Chicco. Кейс Chicco открывает все 11 карточек по порядку; школьный сайт открывает интерактивный прототип, а презентация — отдельный просмотр всех 17 слайдов. Похожие изображения «Кошкин дом» сведены к одной работе. «Центр помощи новичкам» находится в категории «Баннеры».

Контекст СП5 в кейсе основан на [официальном сайте 5opka](https://5opka.ru/) и [сообщении канала 5opka о завершении пятого сезона](https://t.me/joper5/14074). Глеб представлен автором некоммерческих графических материалов для сообщества.

## Как добавить новую работу

1. Скопируй подготовленное изображение в assets/work/. Лучше использовать короткое латинское имя без пробелов, например 36.jpg.
2. В projects.js найди нужный кейс и добавь объект в его массив images. Пример:

    {
      src: "assets/work/36.jpg",
      caption: "Название работы",
      category: "Постеры",
      alt: "Короткое описание изображения"
    }

3. Для category используй одно из значений фильтра: Айдентика, Постеры, Соцсети, Баннеры, Интерфейсы, Презентации или Карточки товара. Значение «Все» добавляется автоматически.
4. Сохрани файл и обнови страницу.

Если это новая серия, создай отдельный объект в window.PORTFOLIO_PROJECTS: задай уникальные id, title, category, cover и images. Для объединённого мини-блока добавь archiveAsProject: true и короткий archiveBadge. Так серия появится в архиве одной карточкой, а изображения откроются в кейсе по порядку. Для самостоятельного кейса добавь featured: true. Для презентации укажи type: "presentation" и список слайдов в images; архивная карточка откроет просмотрщик с первого слайда.

Портфолио строится из данных projects.js, поэтому добавление изображений в массив кейса автоматически добавляет их и в архив с фильтрами.

## Как изменить информацию

- Описание и аватар находятся в index.html. Замени картинку assets/about/avatar.jpg новой подготовленной копией с тем же именем, чтобы не менять разметку.
- Контактная ссылка Telegram задана в index.html у кнопки внизу страницы. Замени адрес https://t.me/show3nnn на свой.
- Заголовки, подписи, описания кейсов, категории и состав серий находятся в projects.js.
- Цвета и размеры находятся в начале styles.css в блоке :root.

## Бесплатная публикация на GitHub Pages

### 1. Создай аккаунт

Открой github.com и выбери Sign up. Укажи адрес почты, придумай имя пользователя, подтверди почту и войди в аккаунт. Имя пользователя будет частью адреса сайта.

Для бесплатного GitHub Pages репозиторий должен быть публичным. До публикации проверь, что в папке сайта нет личных данных, которые не предназначены для открытого доступа.

### 2. Создай новый репозиторий

На GitHub нажми New repository и укажи владельцем свой аккаунт.

Выбери Public, если аккаунт бесплатный, и один из двух вариантов:

- Персональный сайт: назови репозиторий строго username.github.io, заменив username на имя своего аккаунта. Сайт будет открываться по адресу https://username.github.io/.
- Сайт проекта: назови репозиторий, например gleb-portfolio. Сайт будет открываться по адресу https://username.github.io/gleb-portfolio/.

Первый вариант использует корневой адрес GitHub Pages аккаунта. Второй сохраняет имя репозитория в адресе. Для второго варианта относительные пути в этом сайте уже подготовлены. При создании оставь Add a README file выключенным: готовый README.md уже есть в папке сайта.

### 3. Загрузи сайт через веб-интерфейс

1. Открой созданный репозиторий.
2. Нажми Add file → Upload files.
3. Открой папку portfolio-site на компьютере и перетащи в окно GitHub всё её содержимое: index.html, styles.css, projects.js, app.js, README.md, папки assets и demos. Здесь меньше 100 файлов, а школьный макет размером около 22,5 МБ помещается в лимит веб-загрузки GitHub 25 МиБ на файл.
4. Загружай именно содержимое папки, чтобы index.html оказался в корне репозитория. Не загружай исходную папку «работы».
5. Внизу страницы укажи сообщение, например Add portfolio site, и нажми Commit changes.

### 4. Включи GitHub Pages

1. В репозитории открой Settings.
2. В меню слева выбери Pages.
3. В разделе Build and deployment выбери Deploy from a branch.
4. В источнике публикации выбери ветку main и папку /(root).
5. Нажми Save.

GitHub покажет адрес сайта в разделе Pages. После первой публикации дай GitHub несколько минут на сборку. Если сайт не открылся, проверь раздел Actions в репозитории: там виден статус публикации и возможная ошибка.

### 5. Проверь и обновляй сайт

Открой показанный GitHub Pages адрес и проверь главную страницу, фильтры, кейсы, мобильное меню и школьный прототип. После изменений загрузи обновлённые файлы в тот же репозиторий и подтверди Commit changes. GitHub Pages опубликует новую версию автоматически.

Если меняешь файл изображения, сохрани его имя и путь или одновременно обнови поле src в projects.js.

### 6. Собственный домен

В Settings → Pages укажи свой домен в поле Custom domain и сохрани. Затем у регистратора домена настрой DNS записи, которые GitHub покажет для выбранного домена, и дождись их обновления. После проверки включи Enforce HTTPS, если переключатель доступен.

Перед настройкой сверь текущие шаги с официальной документацией GitHub:
- Настройка публикации из ветки: https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site
- Имена репозиториев и создание сайта: https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site
- Подключение своего домена: https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site

## Примечания

Референсная подача переосмыслена через крупную титульную типографику, ясные разделы, серийную подачу работ и небольшие графические акценты. В собственных кейсах сохранены реальные изображения и фактические формулировки.

Работы для СП5 и факультета ИиВТ представлены как некоммерческие серии. Карточки Chicco описаны как авторская работа для маркетплейсов без утверждения об официальном контракте. В школьном кейсе прототип отделён от оболочки портфолио и запускается в изолированном iframe внутри CSS-рамки телефона; исходный файл скопирован без изменения дизайна. Презентация преобразована в 17 изображений слайдов и использует общий просмотрщик с навигацией, кнопкой закрытия и управлением стрелками клавиатуры; на смартфоне доступен свайп.
